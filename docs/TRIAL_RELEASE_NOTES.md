# DSH Launcher 0.4.0 受控试用说明

> 已知缺陷：此旧候选包在 Windows 10 实体机发现安装版本与界面确认版本不一致，停止作为新一轮测试入口。0.4.1 修复候选正在验证；新制品身份以通过 CI 后更新的 candidate.json 为准。旧包及测试现场保留用于追溯。

候选编号：`0.4.0-trial-ci33835360786`。本编号标识测试包，不代表正式 Release 或新的应用版本。

## 本轮变化

- 全新安装使用当前用户目录，不再依赖开发电脑的固定 D 盘环境；保留真实旧安装的兼容路径。
- 首次使用串联环境检查、安装校验、启动健康检查三步，并支持安装前配置目录。
- 增加诊断摘要、日志入口和失败重试提示。
- 修复普通本地构建因更新插件缺少配置而启动即退出的问题；空配置不启用远程更新。
- 增加从零 Runtime、安装后启动和卸载数据保留的自动化验收。

## 已知限制

- 安装器未签名；SignPath Foundation 未批准申请，不声称已签名或获得任何官方背书。
- 这是联网安装型启动器，ZIP 不包含 Node/DSH Runtime；首次安装需要访问官方 Node/npm 源，可能受网络、代理或安全软件影响。
- 远程更新未启用；后续测试版本由维护者明确提供，不会自动切换到未知制品。
- 已安装 Runtime 后不支持直接迁移目录；需要另行设计迁移和恢复流程。
- 上游仍为 developer preview；打开 DSH 页面不代表 API 配置、模型请求及所有上游功能已经验收。
- 只使用测试数据。现阶段不建议将此包作为重要工作流的唯一运行环境。

## 与正式发布的区别

不使用 `RELEASE_TEMPLATE.md` 的签名发行文案，不改变正式发布工作流的签名门禁，不生成 updater 清单、不上传 GitHub Release。
本包仅重组已通过 CI 的安装器和试用材料，不捆绑或转发 DSH Runtime 二进制；正式 Runtime 分发的许可材料仍按发布门禁处理。
