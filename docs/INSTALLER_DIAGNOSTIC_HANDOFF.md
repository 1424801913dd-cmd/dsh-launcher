# 测试端 Codex 接手：0.4.1 安装器误判采证

本文是诊断背景与操作边界，不覆盖测试电脑用户的授权和安全约定。

## 当前状态

- 测试端 Windows 10 Home China 22H2 x64，build 19045.6466，普通 0.4.1 候选进入“已安装”页面后无法卸载，安装验收为 FAIL。
- 报告称旧环境已改名隔离，精确卸载键及四视图筛查均为空；这些是当时观察，接手需重新核对，不据此删除更多目录。
- 界面的“旧的”来自模板年龄描述，不是具体版本号。因此“版本号为空”仍不是已证明的根因；需看安装器实际读到的 DisplayVersion。
- 本包只提供只读诊断。普通候选仍为 `0.4.1-trial-ci33857469193`，本包不替换其身份、不将缺陷标为已修复，也不记为桌面 PASS。

## 身份与技术边界

诊断制品身份、源码提交、CI 和 EXE 摘要见 `candidate.json`。EXE 名为 `DSH-Launcher-INSTALLER-DIAGNOSTIC.exe`；哈希不匹配时不运行。
内部产品名、制造者、当前用户安装模式与 0.4.1 保持一致，以复现其注册表读取；窗口仍可能写“DSH Launcher 安装”，这不代表它可以安装。
模板源自 [Tauri CLI 2.11.4](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.11.4/crates/tauri-bundler/src/bundle/windows/nsis/installer.nsi)，原检测/版本比较逻辑保留，增加了以下证据：

- 运行账户、账户类型、进程号、当前用户上下文及目标注册表视图；
- HKCU/HKLM 的 32/64 位视图中，精确卸载键的默认值、DisplayVersion、UninstallString，以及制造者安装位置键；
- 原 PageReinstall 的实际读取结果、是否命中 WiX 分支、比较前版本与比较结果；
- 是否跳过维护页、进入维护页，以及在安装/卸载动作处被阻断的记录。

NSIS 的账户类型字段不是完整的进程提权证明。请另行如实记录运行账户是否与上次一致、是否使用“以管理员身份运行”、是否出现 UAC；不为了测试改变启动方式。

所有安装 Section 与卸载执行已禁用，源模板中无 Exec、WriteReg、DeleteReg、Delete、创建快捷方式或复制应用文件命令。不会安装启动器、下载 WebView2/Runtime、启动 DSH 或变更旧数据；只在 EXE 所在目录创建新的日志，NSIS 自身会使用临时插件目录。它也不能修复卸载入口。

## 操作顺序

1. 不卸载、不改名、不清理任何现存项目目录、注册表或原有归档。记录当前相关程序是否已退出，不按全部 node.exe 一刀切结束进程。
2. 把完整 ZIP 解压到本机可写的新目录。对照维护者提供的摘要验证 EXE；确认执行的是文件名带 `INSTALLER-DIAGNOSTIC` 的文件，不是旧普通安装器。
3. 在出现问题时的同一账户下双击运行。不要改成管理员运行、不要加 `/S` 或 `/P`，这轮需要普通交互路径。
4. 经过欢迎与许可页面，观察下一页。若出现“已安装”，立即截图并记录两个选项和默认选中项；无需点击下一步/卸载。若直接进入安装目录选择页，也截图并记录“本轮未复现”。
5. 取消或关闭此诊断窗口。不要选择“请勿卸载”继续测试，不尝试完成真正安装。若误点到动作入口，程序会记录 blocked，可能停在维护页或退出，这是只读保护，不是修复成功。
6. 找到 EXE 同目录的 `installer-diagnostic-<PID>.log`，检查有开头 `format=dsh-installer-diagnostic-v1` 和所见页面对应的 decision。若没有日志、路径不可写或被安全软件拦截，保留提示并停止，不反复切换权限猜测。
7. 在本机检查日志，保留字段名、读取成功/失败、版本、通道/分支信息；将账户名与个人路径前缀替换成稳定占位符。卸载命令只作为数据阅读，不执行。发现令牌、密码、网络凭据或不明敏感参数则先遮盖并说明遮盖字段。
8. 回传 `FEEDBACK.md`、必要截图和脱敏日志。原始日志和旧故障现场继续在测试机受控保存，不上传完整用户目录或归档。

## 判读与后续

- `decision=no-existing-install`：该次诊断的实际检测没有命中旧安装；不代表先前报告无效，需比较运行上下文与原安装器行为。
- `decision=maintenance-page`：结合前面的 nsis-detection 或 wix-match、oldVersion 和 semverResult 定位实际来源，不自行删除命中的键。
- `action=uninstall-blocked` / `action=install-blocked`：表示保护已阻断操作，不是正常卸载或安装成功。
- 日志中读取失败或缺失写为 `read-error-or-missing`，不能仅凭这一值区分“键不存在”和“权限拒绝”；不要把它自动解释成清理不彻底。

CI 的真实页面导航只证明采证路径与阻断安全性，不证明 Windows 10 原缺陷已复现/修复。其中 `old-valid` 是模拟旧卸载记录和一个可执行占位件，并非实际旧版本升级/卸载验收；`orphan-default` 与 `missing-uninstaller` 也都是一次性 runner 内的受控夹具。
采证完成后暂停，等待维护者分析；可安装的修复候选另行提供。
