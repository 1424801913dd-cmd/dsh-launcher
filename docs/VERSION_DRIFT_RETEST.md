# 0.4.1 版本漂移修复与复测边界

对应测试端报告：`DEFECT-REPORT-recommended-version-drift.md`。本文件说明修复与验证范围，不代替测试端验收结果。

## 已定位的产品缺陷

0.4.0 的初始前后端快照包含硬编码推荐/Alpha 版本，首次安装无需先成功查询；安装命令仅传通道，后端在执行时重新解析标签。因此界面确认值没有约束实际安装目标。不能仅凭事后 npm 页面断定安装时 registry/CDN 返回了错误标签。

## 0.4.1 的行为

- 初始版本未知；查询失败后不允许继续使用旧查询值安装。启动后尝试查询，也可手动刷新。
- 点击时复制通道和精确版本为不可变请求，后端检查该版本与成功查询的快照一致。
- 下载前再次核对标签；若已变化则停止、报告确认值和本次响应值，要求重新查询和确认，不静默改装。
- 只请求精确版本的 manifest；校验 manifest、实际包/CLI、Runtime 记录，并在首次激活前再次核对目标。
- 对推荐版与 Alpha 同样适用。失败不自动切换或覆盖原有活动 Runtime；不会追溯删除 0.4.0 已经装入的 Runtime。

## 自动化证据如何阅读

- 前端 4 项测试：初始/失败未知版本、推荐版和 Alpha 不可变点击请求、缺失目标和忙碌状态。
- Rust 常规套件包括本地 HTTP 响应序列：两通道标签向前/向后变化、缺失与 503、精确 manifest 路径、错误 manifest/缓存记录及激活不一致；确认未执行安装且原指针保留。不是伪造公网 npm，也不是桌面 UI 自动化。
- `ci-runtime.json` 是推荐版真实从零安装/隔离 smoke 的证据；`versionConsistency` 给出本次 expected/package/runtime/active 版本，必须一致。它不代表 Alpha 真实联网安装已验收。
- `ci-installer.json`、`ci-installer-passive.json` 分别记录静默及带进度界面安装；检查安装后和首次启动后的卸载注册项、卸载后的移除及数据标记保留。
- `ci-startup.json` 只证明已安装启动器初始化且未立即退出；不证明首次向导、托盘或 Windows 应用列表的完整人工体验。

## 卸载入口附加观察

生成的 NSIS 脚本含当前用户卸载注册表写入，尚无证据证明与版本漂移是同一原因。本轮增加四视图只读检查和两种安装模式的自动验证，不通过手工补写注册表掩盖测试端现象。
Server CI 是否复现与测试端 Windows 10 是否复现分别记录；只有测试端完成应用列表及卸载复测，才能关闭其桌面缺陷。
