## 第一阶段：只读盘点

先向用户确认是否有重要数据；不要求其展示任何密钥或完整配置内容。优先核对现有安装记录、已存在的路径元数据及进程信息。
如果旧程序尚未运行，不要仅为盘点而先启动它：启动可能重新创建目录或导入旧 Runtime，改变待记录的基线。
若旧程序已在运行，可记录其界面显示的路径和版本，但同样不要直接执行更新、安装或清理操作。

以下只是源码中的候选位置，**不是这台电脑的已确认目录，更不是删除清单**。自定义路径、环境变量或更早版本可能使用不同位置。

| 类别 | 候选位置/线索 | 处理边界 |
| --- | --- | --- |
| 启动器程序 | Windows 应用列表、安装位置、快捷方式目标 | 确认版本及安装方式后再商定卸载；不猜固定安装目录 |
| 用户级设置 | `%LOCALAPPDATA%\DSH Launcher\settings.json` | 只核对路径字段；不上传整个文件；不存在也应记录 |
| 当前默认 Runtime/缓存 | `%LOCALAPPDATA%\DSH Launcher\runtime`、`%LOCALAPPDATA%\DSH Launcher\cache` | Runtime 可能含多版本/指针；缓存可能有日志及备份，不一概当垃圾 |
| 当前默认用户数据 | `%LOCALAPPDATA%\DeepSeek Harness\home` | 可能含会话、凭据、附件，默认保留 |
| 当前默认工作区 | `%USERPROFILE%\Documents\DSH Workspace` | 可能是用户项目，默认保留 |
| 早期受管 Runtime/缓存 | `D:\Tools\dsh-launcher`、`D:\Caches\dsh-launcher` | 记录 `active.json`、`previous.json`、版本记录所指路径；不只删指针 |
| 早期用户数据/工作区 | `D:\Caches\deepseek-harness\home`、`D:\Bian_CHENG\dsmax` | 不假定仅供测试；可能是重要工作区 |
| 早期独立 Node | `D:\Tools\node-v24.19.0-win-x64\node.exe` | 可能被其他软件共用；不得整目录随意搬移/卸载 |
| 早期独立 DSH | `D:\Tools\dsh-runtime-0.1.1-rc.2\node_modules\@deepseek-ai\dsh\lib\bin.js` | 与上一行同时存在时，候选版可能在没有活动指针时自动导入旧 Runtime |
| 显式配置 | `DSH_LAUNCHER_RUNTIME_ROOT`、`DSH_LAUNCHER_CACHE_ROOT`、`DSH_LAUNCHER_DSH_HOME`、`DSH_LAUNCHER_WORKSPACE`、`DSH_LAUNCHER_SETTINGS_PATH` | 只核对这些路径变量的进程/用户/机器级设置，不导出完整环境变量或其他凭据 |

还需核对实际指针和设置引用的自定义目录；候选位置清单不是所有历史版本的穷举。
不要向新建的空目录写入标记来“检查旧目录是否存在”。盘点只记录必要路径、归属、大小/存在性和版本，不遍历或输出会话正文。

交付用户一份简短盘点表：路径、用途、是否属于本项目、是否共用、是否可能有用户数据、拟保留/备份/隔离动作。归属不明的条目默认保留。

## 第二阶段：选择兼容性测试或全新安装测试

### A. 保留旧环境的兼容性试用（优先考虑）

在确认用户数据备份可用、用户同意试装后，使用核验过身份的候选安装器验证旧安装识别、目录沿用和数据保留。
记录旧版本、新版本、安装前后路径和结果，不默认覆盖安装一定被支持；安装器拒绝或出现不明权限提示时保留现场反馈。
这一轮是旧环境兼容性证据，`BaselineClean` 应为 `NO`，不能将首次向导等未出现的项目填为 `PASS`。

### B. 隔离旧状态后的首次安装测试

仅在用户明确要求此轮测试、并同意精确操作清单后推进：

1. 记录旧版本、安装位置、指针/设置关联与恢复方案；让用户确认需要保留的数据，不在回复或日志中展示凭据。
2. 正常停止 DSH、退出启动器托盘；核对属于该实例的进程确已结束。不按所有 `node.exe` 或端口一刀切杀进程。
3. 在用户指定的安全位置备份本项目必要数据，验证复制完整性与恢复可行性。备份可能包含密钥，只保存在该电脑的受控目录，不上传到 Issue、仓库或对话。
4. 按已确认的安装方式卸载旧启动器；卸载不代表清空 Runtime/DSH_HOME/工作区。
5. 对确认为本项目专用、没有共享使用的残留目录，优先改名或移到本机归档位置，而不是永久删除。逐项记录原路径、归档路径、时间和恢复方法；目标已存在、发现符号链接/目录联接或归属不明时停止。
6. 任何移动/删除前先解析源与目标的绝对路径，验证都在用户确认的范围内。不操作磁盘根、用户主目录、整个 `D:\Tools`、`D:\Caches`、`D:\Bian_CHENG` 或共用 Node/工作区；不要拼接跨 shell 的递归清理命令。
7. 再检查旧固定路径、独立 Node/DSH 自动导入入口、环境变量和用户设置是否仍会被识别。只改一个文件夹名、只删 `active.json` 或新建账户都不充分。
8. 如共用 Node/DSH、开发工具或生产数据无法安全隔离，就放弃把该环境计为严格干净机，继续兼容性试用即可；不要为凑齐验收而移除其他软件。
9. 记录安装前的实际基线；符合 `WINDOWS_ACCEPTANCE.md` 条件才填 `BaselineClean YES`。保留归档直到用户确认新环境及数据都正常，再另行决定是否清理。

文档没有自动清理命令。不要在这台日常实体电脑执行仓库中的 `test-installer.ps1 -IsolatedEnvironment`，也不要运行会故意杀进程/损坏文件的开发测试脚本。
本 ZIP 的 `collect-windows-acceptance.ps1` 和 `inspect-installed-launcher.ps1` 仅作只读收集并写本地报告，不自动决定机器是否干净，也不执行安装/卸载或修复注册表。

## 本次复测顺序（先版本一致性，再继续产品流程）

1. 保留 0.4.0 的错误现场和更早归档；先核对文件哈希、必要日志、`active.json`/`previous.json` 的版本和引用关系，不上传完整配置。0.4.1 不会自动删除或纠正已经装入的 `0.1.2-rc.1`，也不提供无依据的自动降级。
2. 在与原安装相同的 Windows 账户下，安装新包前记录 Windows 应用列表，并按需运行下方只读注册表检查。缺少卸载项时不要自行创建项掩盖问题；若无法正常卸载，先反馈并让用户确认后续精确方案。
3. 本轮优先做“隔离旧状态后的首次安装”：采用上文 B 流程，用户批准后精确隔离此次失败环境，另用全新归档名称，不覆盖测试前旧归档。无法安全隔离则标为兼容性复测，不声称首次向导通过。
4. 安装 0.4.1，确认未知版本时安装按钮不可用，查询成功后才显示精确目标。不要预先要求版本必须是 `0.1.1-rc.2`；标签可能变化，以本次查询和用户实际确认的值为准。截图记录点击前的通道、版本和时间。
5. 默认推荐版安装结束后，核对点击前版本、界面实际版本、版本目录、实际 `node_modules\@deepseek-ai\dsh\package.json`、`runtime.json`、`active.json` 一致；记录字段即可，不修改它们来凑齐结果。任何不一致立即停止，保留证据，不进入正常启动。
6. 若提示目标已变化，应保持旧活动环境不变；重新查询、查看新版本并再次明确确认后才能重试。标签漂移、标签缺失和异常响应已由开发侧本地 HTTP 回归模拟；测试端不要修改 hosts、劫持 npm 或人为损坏日常环境来强造场景。
7. 查询失败/断网后，不应继续用硬编码或上次残留版本安装。恢复网络、重新查询并确认后重试。Alpha 使用同一锁定规则；如用户愿意加测，单独记录 Alpha 实际确认值和安装结果，不能代替推荐版主流程。
8. 版本一致性通过后，再继续首次向导 3/3、启动/打开/停止、托盘与重启保持状态等流程。最后按 `READ-ME-FIRST.md` 进行 Windows 应用列表卸载与数据标记保留测试。

### 卸载入口：独立证据，不与版本漂移混为一谈

在**原安装账户**的普通 PowerShell 中，可于新安装前、安装后、首次启动后及卸载后分别运行（每次使用新报告文件名）：

```powershell
.\inspect-installed-launcher.ps1 -ReportPath '.\uninstall-registration-before.json'
```

此脚本连同 `launcher-uninstall-registry.ps1` 放在同一目录；只读取 HKCU/HKLM 的 32/64 位视图，不联网、不修复、不执行卸载命令。执行策略阻止时记录现象，不降低全局策略。
报告含本地路径，回传前脱敏。预期安装后可见当前用户卸载记录，DisplayVersion 为 `0.4.1`，路径指向实际程序/卸载器；正常卸载后记录移除。还要人工核对 Windows“应用和功能”是否可见，不能仅凭脚本有记录代替界面验证。
如果注册表与应用列表结果不同，分别记录；若两者均缺失，不直接删目录“完成卸载”。CI 的 Server 环境结果不是这台 Windows 10 的结论。

## 恢复与停止条件

- 任何目录归属、重要数据状态或恢复方法无法确认时，停止变更并向用户说明，不猜测“应该没用”。
- 如果隔离后需要恢复：先停止新实例并保留其新数据，不把旧归档直接覆盖到新目录；与用户确认冲突处理后，再按清单恢复相互匹配的旧目录、设置和指针。
- 候选版不提供自动启动器降级；旧版安装器是否能重装、数据是否兼容需要另行核对。没有已验证上一 Runtime 时，不伪造回滚记录。
- 不关闭 Defender、不改全局执行策略、不放宽整盘 ACL。SmartScreen 阻止或来源不确定时暂停反馈。

## 回传给原维护者

先填写 `FEEDBACK.md`；必要时由用户批准运行记录脚本，按真实系统选择 `ExpectedWindows`，实体电脑填 `EnvironmentKind physical`。
尚未盘点时 `BaselineClean UNKNOWN`；旧环境兼容性轮次填 `NO`。默认观察项均为 `NOT_RUN`，不得照抄一组 `PASS`。

回传应包括：

- 安装前旧版本、系统/build、实体机类型及是否满足干净基线；
- 盘点结论、用户批准了哪些动作、实际改动的精确范围、归档及恢复清单（外发时遮盖个人路径）；
- 本轮属于兼容性还是首次安装，分别填写观察表，不混合两轮证据；
- 候选安装器哈希、报错与时间点、必要的脱敏诊断和截图；
- 未执行项、失败项、是否已恢复旧状态，以及下一步需要用户决策的事项。

只提供必要的脱敏信息，不上传备份、完整日志目录、账户配置、密钥或聊天记录。原维护者不会仅凭本说明将桌面验收判为通过。
