# 只读安装器诊断包：不是修复版，不会安装软件

本包用于定位 0.4.1 在测试端错误进入“已安装”页面的问题。**不是 0.4.2 修复候选，也不能用于完成安装验收。**

1. 解压到当前账户可写的新目录，不在 ZIP 内运行；先读 `CODEX-HANDOFF.md`。
2. 核对 `candidate.json`、`SHA256SUMS.txt` 和维护者另行提供的哈希。
3. 双击 `DSH-Launcher-INSTALLER-DIAGNOSTIC.exe`，以出现问题时的同一账户、同一种启动方式操作，不额外提权。
4. 正常经过欢迎/许可页面；出现“已安装”就停止并截图，不选择“请勿卸载”绕过。若进入安装目录选择页，也停止并记录。
5. 关闭诊断窗口，把同目录新生成的 `installer-diagnostic-数字.log` 留在本机。另一位助手先检查脱敏，再填写 `FEEDBACK.md` 回传。

安全说明：保留原模板的检测与维护页流程，但实际安装、卸载、注册表写入、创建快捷方式和启动应用的命令已移除。即使误点到安装/卸载入口也会被阻断，不会修复或清理旧环境。NSIS 会解压自身的临时插件；持久输出仅为本地诊断日志。文件名带 DIAGNOSTIC，约百 KB，不是此前约 2 MB 的普通安装器。

日志是带 BOM 的 UTF-16LE，记事本可读；包含账户名、本地路径和注册表中的卸载命令。**不要直接把未检查的日志公开上传；不要执行日志中的命令。**
包内不含 API Key、用户设置、会话、Runtime 或开发依赖，不自动联网回传。诊断 EXE 未签名；系统拦截时记录并停止，不关闭 Defender、不降低全局策略。

旧 0.4.0/0.4.1 的错误现场与归档保持原样。收到日志后，开发端才能按证据定位修复并另出可安装候选。
