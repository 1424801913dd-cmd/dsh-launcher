# DSH Launcher 小范围试用：先读这里

本包仅供项目所有者及受邀测试者使用，不是正式稳定版。项目非官方、独立维护，未经 DeepSeek 审核或背书。

## 这是什么包

- 候选编号：`0.4.0-trial-ci33835360786`，应用显示版本仍为 `0.4.0`。
- 安装器来自已通过自动化检查的 [CI 运行](https://github.com/1424801913dd-cmd/dsh-launcher/actions/runs/33835360786)，不是重新编译的另一份文件。
- 安装器没有 Authenticode 签名；远程启动器更新与签名 Runtime 更新均未启用。首次安装仍会联网下载 Node/DSH 并运行 npm 安装脚本。
- Windows 10/11 桌面验收尚未完成；CI 在 Windows Server 上通过不等于日常桌面体验已验收。
- 不含预装 Runtime、个人设置、API Key、会话、日志或开发环境；无需自行安装 Node、npm、Git、Rust。

## 在另一台电脑开始前

**已知情况更新：第二台电脑在旧状态隔离后测试 0.4.0，发现“确认版本与实际安装版本不一致”。错误 Runtime、日志和更早旧环境归档均需保留；0.4.1 不会自动纠正已有错误安装。先按交接文档准备独立复测状态，不直接清空或覆盖归档。**
那台电脑若由另一位 Codex 助手协助，请先让它阅读包内 `CODEX-HANDOFF.md`，完成只读盘点并向你说明方案；这份文档本身不是删除、迁移或卸载授权。
此次修复、自动化证据的范围及仍待实测项见 `VERSION-DRIFT-RETEST.md`。

1. 使用 Windows 10/11 x64 的实体电脑即可，不必安装虚拟机。一台电脑只证明它实际运行的 Windows 版本。
2. 先记录系统版本，以及是否已安装 DSH Launcher、DSH、Node、Git、Rust。若已有这些环境，先做兼容性试用，不将其记作干净机首次安装通过；不要为了测试删除日常环境。
3. 不要在已有重要 DSH 数据的账户上直接试装。优先选择无生产 DSH 数据的测试账户和独立工作区，不导入真实会话、密钥或重要项目。
4. 通过双方确认的渠道拷贝整个 ZIP，解压后阅读本文件；不要在压缩包内直接运行。需要联网完成首次安装，预留足够磁盘空间。
5. 本包没有自动安装/卸载脚本。不要在实体电脑运行维护者的 `test-installer.ps1 -IsolatedEnvironment`；该脚本只用于可丢弃环境。

### 已装过旧版：先保留，不直接清空

- 已产生的目录未必是不需要的文件：Runtime、缓存、配置、聊天记录、凭据和工作区必须分开判断。不要把整个 `D:\Tools`、`D:\Caches` 或 `D:\Bian_CHENG` 删除。
- 先记录旧版版本、真实安装路径、Runtime/缓存/DSH_HOME/工作区位置及是否有重要数据；在确认备份和用户同意后，可先做旧环境兼容性试用，单独记录，不能当作首次安装验收。
- 若之后需要测试全新安装，先确认本项目进程已停止，备份必要数据并验证备份；由用户确认具体卸载、改名归档和恢复方案后，再逐项隔离本项目专用目录。不要提供或执行“一键清空”命令。
- 卸载启动器刻意保留 Runtime 和用户数据；新建 Windows 账户也可能继续命中早期固定 D 盘路径。只删 `active.json`、只改一个目录名或只卸载 EXE，都不足以证明已恢复干净状态。
- 旧版独立 Node/DSH 路径仍存在时，当前候选版可能再次自动导入旧 Runtime。应核对所有已知入口及路径配置，不能把再次显示“已安装”简单归因于缓存。
- 无法确认目录归属、发现共用 Node/真实工作区或无法安全隔离时，保留原状，只做兼容性试用；验收基线填 `NO` 或 `UNKNOWN`，不要为了得到 `PASS` 删除日常环境。

详细候选路径、操作边界、恢复记录和回传要求见 `CODEX-HANDOFF.md`（仓库源文件为 `docs/TEST_MACHINE_HANDOFF.md`）。

## 核对身份再安装

安装器文件名：`DSH Launcher_0.4.0_x64-setup.exe`。

SHA-256：`949744407DABBCA21CD0AA3D7CE4F8FC93FDC2C935FCCD03E6081DF1ADA6E0DF`。

可在解压目录打开 PowerShell，执行只读检查（不是产品运行前提）：

```powershell
Get-FileHash -LiteralPath '.\DSH Launcher_0.4.0_x64-setup.exe' -Algorithm SHA256
```

与项目所有者另行提供的摘要或 CI 来源核对；ZIP 内自带的摘要不能单独证明来源可信。摘要不一致时停止，不要运行。
`SHA256SUMS.txt` 列出包内其余文件的校验值，`candidate.json` 记录源码提交和 CI 身份。

Windows 可能提示未知发布者或 SmartScreen 警告。请记录真实提示，不关闭 Defender、不添加全局排除、不修改系统安全策略。
如果系统阻止执行或你无法确认来源，停止并反馈。若通过 U 盘复制后未出现 SmartScreen，也只能记录“未显示”，不能声称产品已建立声誉。

## 第一轮：只测试默认路径

按普通用户操作并记录每步结果；不用开发命令或复制本机 Runtime 来帮助产品启动。

1. 双击安装器，完成当前用户安装并打开启动器。
2. 观察首次向导 1/3 的 Windows、WebView2、磁盘及目录提示，先保留默认路径。
3. 等待版本查询成功，记录推荐版按钮上的精确版本和点击时间后安装。查询失败时安装应不可用；若提示目标已变化，重新查询并明确确认后才能重试。安装结束后按 `CODEX-HANDOFF.md` 核对界面、实际包、Runtime 记录与活动指针版本一致，再进入启动阶段。
4. 点击启动并等待健康检查通过，再打开 DSH 页面。记录是否可打开，不必填写真实 API Key；这不等于已经验证模型调用。
5. 关闭启动器窗口，检查托盘能否恢复；点击停止，确认原 DSH 页面不再提供服务；最后通过托盘退出。
6. 重新打开启动器并再次启停，确认已安装状态保留。

各步骤分别填写 `FEEDBACK.md`。打不开、报错或出现不理解的权限提示时，保留现场，不反复删除目录尝试。

## 第二轮：异常和数据保留

- **中文路径**：使用另一套干净测试状态，首次安装前配置包含中文和空格的路径，保存重启后核对。已有 Runtime 后路径会锁定；不手动删活动指针解锁。
- **断网重试**：只在测试电脑暂时断网，观察可理解的失败提示；恢复网络后重试。不要影响正在使用的远程连接。
- **端口冲突**：需要维护者安排一个可识别的临时外部服务，确认启动器不接管、不结束它；未安排就标 `NOT_RUN`。
- **卸载保留**：先在测试 DSH_HOME 和工作区分别放一个无敏感内容的标记文件，记录位置；停止 DSH 并退出托盘，再通过 Windows 应用列表卸载。核对程序和快捷方式移除，两个标记文件仍在。

先完成第一轮，再按维护者安排做第二轮。不要为凑齐 `PASS` 猜测结果；卸载保留的数据也意味着重新安装并不自动恢复干净状态。

## 遇到故障与回退

复制启动器的“诊断摘要”，配合报错截图和时间点填写 `FEEDBACK.md`；发送前人工检查，不包含令牌、API Key、Cookie、完整会话或个人路径。

Runtime 有已验证上一版本时，可以使用应用内回滚；没有上一版本时不要伪造版本指针。当前预览版不提供自动启动器降级。
若无法继续，停止 DSH、退出托盘，保留测试数据与日志并联系维护者。不要覆盖安装旧版或手动删 Runtime/DSH_HOME；需要回退安装器时先核对数据兼容性和备份方案。

反馈可直接发给项目所有者，或在 [项目 Issues](https://github.com/1424801913dd-cmd/dsh-launcher/issues) 按 `FEEDBACK.md` 内容提交。
仓库另附试用反馈表单，合入默认分支后才会显示为可选模板。
不要把完整诊断日志或账户信息直接发到公开 Issue。

## 记录正式验收结果（可选，由维护者协助）

优先回传填写后的 `FEEDBACK.md`。包内 `collect-windows-acceptance.ps1` 只采集系统信息和人工观察，不安装、不卸载、不联网发送。
维护者可协助运行；如果执行策略阻止脚本，直接回传表格，不要求降低系统执行策略。

```powershell
.\collect-windows-acceptance.ps1 `
  -ExpectedWindows Windows11 -EnvironmentKind physical -BaselineClean YES `
  -InstallerPath '.\DSH Launcher_0.4.0_x64-setup.exe' `
  -ReportPath '.\windows11-acceptance.json'
```

把 `Windows11` 换为实际系统；只有测试开始前满足上述干净条件才填 `BaselineClean YES`。示例未传观察结果，默认全部 `NOT_RUN`，因此返回未完成是正常行为。不能直接复制一组 `PASS` 当作实测结果。
报告含系统版本及本地安装器路径，回传前仍需检查隐私。实体电脑和虚拟机证据均可用，但 Windows 10 与 Windows 11 需要分别实测。
